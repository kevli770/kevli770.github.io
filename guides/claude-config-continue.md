# Continue Automatically At Usage Limit: איך גורמים ל-Claude Code להמשיך לבד ברגע שהמכסה מתאפסת

> כשאתם משאירים את Claude Code רץ על משימה ארוכה, מוקדם או מאוחר הוא נתקע במכסת השימוש. עד לא מזמן זה אומר שהסשן פשוט עומד: המכסה מתאפסת אחרי כמה שעות, אבל אף אחד לא לוחץ להמשיך, אז הזמן שבין הרגע שהמכסה חזרה לרגע שאתם חזרתם למחשב פשוט הולך לפח.

מאת קווין ליאקס. פורסם 2026-08-27. נושא: Claude ו-Claude Code.
העמוד המלא: https://kevli770.github.io/guides/claude-config-continue

## מה זה בכלל

כשאתם משאירים את Claude Code רץ על משימה ארוכה, מוקדם או מאוחר הוא נתקע במכסת השימוש. עד לא מזמן זה אומר שהסשן פשוט עומד: המכסה מתאפסת אחרי כמה שעות, אבל אף אחד לא לוחץ להמשיך, אז הזמן שבין הרגע שהמכסה חזרה לרגע שאתם חזרתם למחשב פשוט הולך לפח.

ההגדרה **Continue automatically at usage limit** פותרת בדיוק את זה: ברגע שהמכסה מתאפסת, Claude Code ממשיך את הסשן מהנקודה שבה נעצר, בלי שתהיו שם.

היא נכנסה בגרסה 2.1.234 ב-17 באוגוסט 2026, וזה הניסוח הרשמי ב-changelog:

*“Claude Code now continues your session automatically when a claude.ai usage limit resets; turn it off in /config (‘Continue automatically at usage limit’)”*

## איך זה נראה כשנתקעים

זאת ההודעה שאתם מקבלים בטרמינל ברגע שנגמרה המכסה. שימו לב לשעת האיפוס בסוף השורה, ולאפשרות הראשונה שמסומנת אוטומטית:

![ההודעה בטרמינל: You've hit your session limit, ומתחתיה האפשרות Wait for limit to reset](https://kevli770.github.io/_astro/01.C7x_mm_e.png)

*ההודעה בטרמינל: You've hit your session limit, ומתחתיה האפשרות Wait for limit to reset*

בלי ההגדרה, האפשרות הזאת מחכה שמישהו יאשר אותה. עם ההגדרה דלוקה, Claude ממשיך לבד ברגע שהשעה מגיעה.

## איפה ההגדרה יושבת

פותחים סשן Claude Code בטרמינל ומריצים:

```
/config
```

נפתח פאנל הגדרות. עוברים ללשונית `Config`, מקלידים בשורת החיפוש `usage limit` ומוצאים את השורה:

![השורה Continue automatically at usage limit בתוך תפריט ה-config](https://kevli770.github.io/_astro/02.B3gSpk-j.png)

*השורה Continue automatically at usage limit בתוך תפריט ה-config*

מנווטים עם החיצים למעלה ולמטה, ולוחצים Enter כדי להחליף בין true ל-false. Esc סוגר את הפאנל.

## חשוב לדעת: אצל רובכם זה כבר דלוק

זאת הנקודה שהכי מבלבלת. ההגדרה הזאת מגיעה **דלוקה כברירת מחדל**. ה-toggle ב-config קיים כדי לכבות אותה, לא כדי להדליק.

אז למה בכל זאת כדאי להיכנס ולבדוק? כי אם עדכנתם מגרסה ישנה, או אם מישהו נגע בהגדרות בעבר, הערך אצלכם יכול להיות false בלי שתשימו לב, ואז תמשיכו לאבד לילות בלי סיבה. בדיקה של עשר שניות סוגרת את הסיפור.

הכלל הפשוט: תוודאו שהערך בשורה הוא `true`. זהו.

## איך מוודאים שזה באמת עובד

- פותחים /config ומוודאים ש-Continue automatically at usage limit נמצא על true
- משאירים ל-Claude משימה אחת סגורה ומוגדרת היטב, לא בקשה פתוחה בסגנון 'תשפר לי את הפרויקט'
- מוודאים שההרשאות שנתתם מתאימות לעבודה בלי שאתם ליד, הוא ימשיך לרוץ כשאתם לא מול המסך
- בבוקר בודקים את הסשן: אם ההגדרה עבדה, תראו שהעבודה המשיכה אחרי שעת האיפוס

ככה זה נראה כשהמכסה מתאפסת וההמשך קורה לבד:

הפיצ'ר קיים בשני המקומות, אבל הוא מתנהג אחרת בכל אחד מהם:

| **איפה מגדירים** | /config, לשונית Config | צ'ק בוקס על כרטיס הלימיט עצמו |
| **כמה פעמים** | פעם אחת. הגדרה גלובלית שתופסת לכל הסשנים | מסמנים מחדש על כל כרטיס לימיט |
| **מאז מתי** | גרסה 2.1.234, 17 באוגוסט 2026 | 13 באוגוסט 2026 |
| **ברירת מחדל** | **דלוק** | **ידני בכל פעם** |

## מה זה לא נותן לכם

שווה להיות מדויקים כדי לא להתאכזב:

- זה לא מוסיף אפילו טוקן אחד. חלון חמש השעות והתקרה השבועית נשארים בדיוק אותו דבר
- זה לא מייצר מכסה חדשה, אלא מנצל את זו ששילמתם עליה במקום לזרוק אותה
- זה לא מריץ משימות חדשות. הוא ממשיך את מה שכבר היה באמצע

**הבעיה שזה פותר היא הזמן המת, הפער בין הרגע שהמכסה חוזרת לרגע שאתם חוזרים למחשב.**

## טיפים

- לפני שאתם הולכים לישון, השאירו משימה אחת מוגדרת היטב בתור, לא בקשה פתוחה
- בקשו מ-Claude לכתוב סיכום קצר של מה שהוא עשה בסוף המשימה, כדי שתדעו בבוקר איפה הוא היה
- עברו על ההרשאות לפני שאתם עוזבים. מה שהוא לא יכול לעשות לבד, הוא יעצור עליו בכל מקרה
- אם הסשן ארוך במיוחד, שווה שיהיה commit ביניים כדי שתמיד יהיה לאן לחזור
- בדקו את /config אחרי עדכון גרסה גדול, שם ההגדרות משתנה מדי פעם
- הפאנל תומך בחיפוש. usage limit מביא אתכם לשורה הנכונה מיד
