## מה זה Claude Design

Claude Design הוא כלי העיצוב של Anthropic שהפך פרומפט בשפה רגילה לתוצר מעוצב: פרוטוטייפ, מסך אפליקציה, מצגת, או מוקאפ שיווקי. הוא הושק כ-Research Preview יחד עם Opus 4.7, ובעדכון של יוני 2026 הוא קיבל את היכולות שהופכות אותו למשהו רציני: ייבוא Design System, עריכה ישירה על קנבס, וסנכרון דו-כיווני עם Claude Code.

**הדבר שבאמת משנה את המשחק הוא הביקורת העצמית: קלוד בודק את עצמו מול הכללים שלכם ומתקן את הטעויות שלו לבד, עוד לפני שאתם רואים את התוצאה. במקום לתקן אחרי קלוד, קלוד מתקן את עצמו לפניכם.**

**איפה:** claude.ai/design (זמין בכל החבילות בתשלום, כולל אפליקציית דסקטופ).

## הבעיה שזה פותר

עד היום קיבלתם תוצאה מ-AI וישבתם לתקן אותה ידנית, כל פעם מחדש. שלוש הבעיות הקלאסיות שחזרו שוב ושוב:

- הצבע לא בדיוק הגוון של המותג.
- הריווח זז, והרכיבים לא מיושרים.
- הקומפוננטה לא תואמת ל-Design System שלכם.

הפתרון הוא לתת לקלוד את הכללים שלכם מראש, ולגרום לו לבדוק את עצמו מולם לפני שהוא מציג לכם משהו.

## שלב 1: לחבר את ה-Design System שלכם

זה הבסיס לכל הביקורת העצמית. בלי הכללים שלכם, לקלוד אין מול מה לבדוק את עצמו. אפשר לייבא משני מקורות:

- מ-Git: ריפו של ספריית קומפוננטות, design tokens, או מקור בסגנון Storybook.
- מקובץ: סטייל-גייד, קובץ tokens בפורמט JSON, או PDF של המותג.

אחרי החיבור, כל מסך שקלוד מייצר יורש אוטומטית את הצבעים, הטיפוגרפיה, הריווח ואוצר הקומפוננטות שלכם, במקום placeholder גנרי.

![ריפו של Design System (קומפוננטות + tokens) שקלוד יכול לייבא ולבנות מולו](https://kevli770.github.io/_astro/01.Yz0gAeXr.png)

## שלב 2: להגדיר את הביקורת העצמית

זה הלב של העדכון. המטרה: שקלוד יבדוק את עצמו מול הכללים שלכם ויתקן את הטעויות לפני שאתם רואים את התוצאה. ככה מגדירים את זה נכון:

- כתבו כללים מפורשים: צבעי המותג המדויקים, סקאלת הריווח, גופנים מותרים, ורשימת הקומפוננטות שמותר להשתמש בהן. ככל שהכללים ברורים יותר, כך הביקורת העצמית מדויקת יותר.
- בקשו מקלוד לבדוק את עצמו: הוסיפו לפרומפט הנחיה כמו 'לפני שאתה מציג לי, עבור על התוצאה מול ה-Design System, סמן כל סטייה, ותקן אותה'.
- תנו לו לסגור את הלולאה: קלוד בונה, בודק מול הכללים, מתקן את הטעויות שלו, ורק אז מציג. מה שמגיע אליכם כבר עבר ביקורת עצמית.
- אתם לא מתקנים, אתם רק מאשרים. אם משהו עדיין לא מדויק, עדכנו את הכלל עצמו ולא רק את המסך, כדי שהתיקון יחזיק לפעם הבאה.

![קלוד בונה מול הכללים שלכם, בודק את עצמו, ומתקן לבד לפני שאתם רואים](https://kevli770.github.io/_astro/02.De-CfVa6.png)

*קלוד בונה מול הכללים שלכם, בודק את עצמו, ומתקן לבד לפני שאתם רואים*

## שלב 3: סנכרון דו-כיווני עם Claude Code

אם אתם עובדים גם בקוד, הפקודה `/design-sync` מחברת בין Claude Design ל-Claude Code בשני הכיוונים:

- משיכה: מריצים את הפקודה כדי למשוך את ה-Design System והמסכים הנבחרים אל תוך הריפו.
- דחיפה: UI שבניתם ב-Claude Code אפשר לדחוף בחזרה ל-Claude Design לליטוש ויזואלי.

ככה הכללים נשארים מקור אמת אחד גם בקוד וגם בעיצוב, והביקורת העצמית עובדת על אותו סטנדרט בשני הצדדים.

```
/design-sync
```

## שלב 4: עריכה על הקנבס וייצוא

כשהתוצאה מוכנה, עורכים אותה ישירות על הקנבס בעריכת WYSIWYG: גרירה ושחרור של אלמנטים ומיקרו-תיקונים בלי לכתוב פרומפט מחדש. אחרי זה מייצאים החוצה:

| יעד | מתי להשתמש |
|---|---|
| **Canva** | העברה לצוות שיווק והמשך עבודה על המוקאפ. |
| **PDF** | שיתוף לבעלי עניין וסבב פידבק. |
| **PPTX** | מצגת להנהלה או ללקוח. |
| **Figma / Vercel** | דרך Claude Code (קוד ל-Vercel) או כלי המרה כמו Anima ל-Figma. אין כרגע ייצוא ישיר ל-Figma מתוך הכלי. |

## לפני ואחרי

| מקבלים תוצאה ומתקנים ידנית כל פעם | **קלוד מתקן את עצמו לפני שאתם רואים** |
| צבע, ריווח וקומפוננטות לא עקביים | הכל יורש את ה-Design System שלכם |

## טיפים

- כללים ספציפיים מנצחים כללים כלליים. 'כפתור ראשי בצבע #da7756 עם רדיוס 12px' עדיף על 'תעצב יפה'.
- תנו לקלוד צ'קליסט קצר לבדיקה עצמית, ובקשו ממנו לדווח אילו סטיות מצא ותיקן.
- כשמשהו לא מדויק, תקנו את הכלל ולא רק את המסך, כדי שזה יחזיק לפעם הבאה.
- התחילו מ-Design System קטן ונקי. עדיף מעט tokens מדויקים מהרבה כללים סותרים.
- אם אתם גם מפתחים, השתמשו ב-/design-sync כדי לשמור על מקור אמת אחד בין קוד לעיצוב.
- ייצאו מוקדם ל-PDF כדי לקבל פידבק לפני שמשקיעים בליטוש סופי.
