## הבעיה: הסוכן מתחיל כל פעם מאפס

קלוד, וכל סוכן AI אחר, שוכח הכל ברגע שסוגרים את החלון. כל שיחה חדשה מתחילה מדף חלק. אין לו מושג מי הלקוח שלכם, אילו החלטות כבר קיבלתם, או מה ההעדפות שחזרתם עליהן עשר פעמים.

התוצאה: אתם מסבירים את אותם דברים שוב ושוב, מתקנים את אותן טעויות, ומאבדים את כל ההקשר שבניתם. במקום סוכן שמכיר אתכם, יש לכם זר חדש בכל בוקר.

**הפתרון פשוט: נותנים לסוכן זיכרון חיצוני. ארבעה קבצים שמחזיקים את מה שחשוב, ושני שלבים פשוטים ששומרים וטוענים אותם אוטומטית. ככה השיחה ה-50 ממשיכה בדיוק מאיפה שהשיחה הראשונה נגמרה.**

## הרעיון בגדול

הזיכרון הפנימי של המודל זמני, הוא חי רק כל עוד החלון פתוח. במקום להסתמך עליו, אנחנו מוציאים את הזיכרון החוצה אל קבצים שהסוכן קורא וכותב בעצמו.

המערכת בנויה משני חלקים:

- ארבעה קבצים: כל אחד אחראי על סוג זיכרון אחר (מה עכשיו, מה היה, מה קבוע, מי אתה).
- שני שלבים: איך הקבצים מתעדכנים בסוף כל שיחה ונטענים בתחילת השיחה הבאה.

זהו. אין צורך בכלי חיצוני או בתוסף. רק קבצי טקסט פשוטים והרגל קבוע.

## ארבעת הקבצים

כל קובץ מחזיק שכבה אחרת של זיכרון. ביחד הם נותנים לסוכן תמונה מלאה:

| הקובץ | מה הוא שומר | דוגמה |
|---|---|---|
| **1. זיכרון עבודה** | מה אתם עושים עכשיו, מה פתוח באמצע, מה המשימה הנוכחית | "בונים דף נחיתה, נשאר לחבר את הטופס" |
| **2. סשנים קודמים** | החלטות שכבר התקבלו ותיקונים מהעבר, כדי לא לחזור עליהם | "בחרנו Tailwind ולא Bootstrap" |
| **3. עובדות קבועות** | מי הלקוח, מה הסטאק הטכנולוגי, מה ההעדפות שלא משתנות | "הלקוח: חברת ביטוח, מעדיף גוון כחול" |
| **4. זהות** | מי הסוכן, מה התפקיד שלו ולמה הוא עובד, כדי שלא ייסחף | "אתה מפתח fullstack שכותב קוד נקי" |

*הקובץ הרביעי, הזהות, הוא העוגן. הוא נטען ראשון תמיד ושומר על הסוכן ממוקד גם כשהשיחה מתפתלת.*

## שני השלבים החכמים

הקבצים לבדם הם רק מגירות ריקות. השלבים האלה הם מה שגורם להם להתמלא ולהיטען בזמן הנכון:

### שלב 1: בסוף כל סשן: שמירה

לפני שסוגרים את השיחה, הסוכן עובר על כל מה שקרה, שולף את מה שחשוב לטווח ארוך, ושומר כל פרט בקובץ הנכון. החלטה חדשה הולכת לקובץ הסשנים, עובדה קבועה לקובץ העובדות, וכן הלאה.

### שלב 2: בתחילת כל סשן: טעינה

בשיחה החדשה הסוכן קודם טוען את הזהות שלו, ואז מושך רק את המידע שרלוונטי למשימה הנוכחית. הוא לא מציף את עצמו בהכל, רק במה שצריך עכשיו.

## איך מיישמים: צעד אחר צעד

### שלב 1: יוצרים את הקבצים

פותחים תיקיית memory ובתוכה ארבעה קבצי markdown:

```
memory/
  working-memory.md   # מה עושים עכשיו
  decisions.md        # החלטות מסשנים קודמים
  facts.md            # עובדות קבועות על הלקוח והפרויקט
  identity.md         # מי הסוכן ומה התפקיד
```

ב-Claude Code אפשר להשתמש בקובץ `CLAUDE.md` כקובץ העובדות והזהות, ולהוסיף את שאר הקבצים בתיקיית memory.

### שלב 2: prompt לסוף הסשן

בסיום כל שיחה, מדביקים לסוכן את ההוראה הזו:

```
עבור על כל מה שקרה בסשן הזה.
שלוף מה שחשוב לזכור לטווח ארוך
ועדכן את הקובץ המתאים:
- החלטה חדשה  -> decisions.md
- עובדה קבועה -> facts.md
- משימה פתוחה -> working-memory.md
```

### שלב 3: prompt לתחילת הסשן

בתחילת כל שיחה חדשה, נותנים לסוכן את ההוראה הזו:

```
לפני שמתחילים:
1. קרא את identity.md  (מי אתה)
2. קרא את facts.md     (עובדות קבועות)
3. מתוך decisions.md ו-working-memory.md
   משוך רק את מה שרלוונטי למשימה הנוכחית
```

*טיפ: אפשר להפוך את שני ה-prompts לפקודות קבועות (slash commands) כדי לא להעתיק אותם ידנית בכל פעם.*

## דוגמה מלאה

ככה זה נראה בפועל:

- סשן 1: סיפרתם לסוכן פרט חשוב על הלקוח. בסוף הסשן הוא שמר אותו ב-facts.md.
- סשנים 2 עד 49: בכל פעם הוא טען את העובדות והמשיך מאיפה שהפסקתם.
- סשן 50, בצ'אט חדש לגמרי: שאלתם אותו על אותו לקוח, והוא ענה נכון, בלי שחזרתם אפילו על מילה.

**זה ההבדל בין כלי שמתחיל מאפס כל בוקר, לבין שותף שמכיר את הפרויקט שלכם לעומק.**

## טיפים

- תתחילו קטן: גם רק קובץ facts.md אחד משפר את החוויה מיד.
- קצר עדיף על ארוך. קובץ זיכרון תפוח מבלבל את הסוכן, שמרו רק את מה שבאמת חוזר.
- הזהות תמיד נטענת ראשונה. זה מה שמונע מהסוכן להיסחף לכיוונים לא רלוונטיים.
- מפרידים בין זמני לקבוע: working-memory מתאפס, facts ו-identity נשארים.
- מעדכנים בסוף כל סשן, לא רק כשנזכרים. ההרגל הוא מה שמחזיק את המערכת חיה.
- אם אותה החלטה מופיעה שוב ושוב, העבירו אותה מ-decisions ל-facts.
- תנו לסוכן למשוך רק את הרלוונטי למשימה, לא את כל הקבצים בכל פעם.
