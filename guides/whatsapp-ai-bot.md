## מה זה WAHA?

WAHA (ראשי תיבות של `WhatsApp HTTP API`) הוא כלי חינמי לגמרי וקוד פתוח (רישיון Apache-2.0) שהופך את הוואטסאפ ל-API פשוט מבוסס REST. במקום להירשם ל-API הרשמי של מטא, לעבור אישורים ולשלם, אתם מריצים את WAHA על השרת שלכם ומקבלים גישה תכנותית מלאה למספר הוואטסאפ, כולל שליחה וקבלה של הודעות, בכמה דקות.

מאחורי הקלעים WAHA מפעיל סשן אמיתי של `WhatsApp Web`, וזו בדיוק הסיבה שהוא עובד על המספר האישי שלכם בלי שום API רשמי ובלי אישורים מיוחדים. הסלוגן הרשמי של הפרויקט: *"WhatsApp API that you can run in a click!"*

**קצת מספרים שמראים שזה לא צעצוע: מעל 1.9 מיליון הורדות ב-Docker, פרויקט פעיל עם עדכונים שוטפים, וקהילה גדולה. הכל פתוח, הכל שלכם.**

## איך זה עובד: הקסם האמיתי

כל הרעיון של בוט חכם הוא לולאה אחת פשוטה של שלושה שלבים. ברגע שמישהו שולח לכם הודעה בוואטסאפ, זה מה שקורה:

- 1. WAHA מקבל את ההודעה הנכנסת ושולח אותה מיד ל-`webhook` שלכם (כתובת שאתם קובעים).
- 2. הקוד שלכם מעביר את טקסט ההודעה ל-`LLM`, מודל שפה כמו GPT או קלוד, ומקבל תשובה חכמה.
- 3. הקוד שלכם שולח את התשובה בחזרה למשתמש דרך `POST /api/sendText`.

**זהו. שלושה שלבים, לולאה אחת, ויש לכם בוט שעונה לבד לכל הודעה שנכנסת, תוך כ-15 דקות של עבודה.**

## איך מתקינים: שלב אחרי שלב

כל מה שצריך זה Docker מותקן על המחשב או השרת. ארבע פקודות ואתם באוויר.

### שלב 1: מושכים את ה-Image

```bash
docker pull devlikeapro/waha
```

### שלב 2: אתחול (יוצר קובץ הגדרות .env)

```bash
docker run --rm -v "$(pwd)":/app/env devlikeapro/waha init-waha /app/env
```

### שלב 3: מריצים את WAHA

```bash
docker run -it --env-file "$(pwd)/.env" \
  -v "$(pwd)/sessions:/app/.sessions" \
  --rm -p 3000:3000 --name waha devlikeapro/waha
```

### שלב 4: פותחים את הדשבורד

נכנסים בדפדפן לכתובת:

```
http://localhost:3000/dashboard
```

## חיבור הוואטסאפ (סריקת QR)

עכשיו מחברים את מספר הוואטסאפ שלכם לסשן. זה בדיוק כמו לחבר את WhatsApp Web בפעם הראשונה:

- פותחים סשן חדש בדשבורד: הסטטוס שלו יעבור ל-SCAN\_QR.
- לוחצים על אייקון המצלמה כדי להציג את ה-`QR`.
- סורקים את הקוד מהוואטסאפ בטלפון (הגדרות \> מכשירים מקושרים).
- ברגע שהסריקה מצליחה: הסטטוס הופך ל-**WORKING** והבוט מחובר.

## שליחת הודעת בדיקה ראשונה

כדי לוודא שהכל עובד, שולחים הודעה דרך ה-API. קוראים ל-`POST /api/sendText` עם מפתח ה-API בכותרת `X-Api-Key`:

```
POST http://localhost:3000/api/sendText
Header:  X-Api-Key: <your-key>
Body (JSON):
{
  "chatId": "123@c.us",
  "text":   "Hi there!",
  "session": "default"
}
```

שימו לב לפורמט של ה-`chatId`, מספר הטלפון (עם קידומת בינלאומית, בלי +) ואחריו `@c.us`. אם קיבלתם את ההודעה בטלפון, הכל עובד.

## הקוד של הבוט (Webhook + LLM)

החלק היחיד שאתם כותבים בעצמכם הוא ה-`webhook`, נקודת קצה שמקבלת כל הודעה נכנסת, שולחת ל-LLM, ומחזירה תשובה. הנה שלד מינימלי ב-Node.js (הרעיון זהה גם בפייתון):

```
// כל הודעה נכנסת מגיעה לכאן מ-WAHA
app.post('/webhook', async (req, res) => {
  const msg = req.body.payload;

  // 1. שולחים את הטקסט ל-LLM (GPT / Claude)
  const reply = await askLLM(msg.body);

  // 2. מחזירים את התשובה למשתמש דרך WAHA
  await sendText(msg.from, reply);

  res.sendStatus(200);
});
```

והפונקציה `sendText` שקוראת בחזרה ל-WAHA:

```
function sendText(chatId, text) {
  return fetch('http://localhost:3000/api/sendText', {
    method: 'POST',
    headers: {
      'X-Api-Key': API_KEY,
      'Content-Type': 'application/json'
    },
    body: JSON.stringify({ chatId, text, session: 'default' })
  });
}
```

**מגדירים את כתובת ה-webhook בהגדרות הסשן ב-WAHA, ומאותו רגע כל הודעה זורמת אוטומטית דרך הלולאה. זה כל הבוט.**

## שלושה מנועים לבחירה

ל-WAHA יש שלושה מנועים (engines) שמריצים את הוואטסאפ מתחת. בוחרים אחד לפי הצורך:

| מנוע | טכנולוגיה | מתי לבחור |
|---|---|---|
| `WEBJS` | דפדפן (Chromium) | ברירת המחדל, היציב והנפוץ ביותר. תומך בהכי הרבה פיצ'רים. |
| `NOWEB` | Node.js WebSocket | קל וחסכוני במשאבים, בלי דפדפן. מהיר יותר לעומסים. |
| `GOWS` | Go WebSocket | הכי חסכוני בביצועים, מבוסס Go. מתאים לפרודקשן בקנה מידה. |

## שימושים נפוצים

- שירות לקוחות אוטומטי: מענה מיידי לפניות 24/7.
- מענה אוטומטי לשאלות נפוצות (FAQ), הבוט עונה במקומכם.
- עוזר אישי: מסכם, מתזכר, מחפש מידע ומגיב בשפה טבעית.
- כמה סשנים במקביל: אפשר לחבר יותר ממספר אחד ולנהל בוטים במקביל.

## אזהרה חשובה: קראו לפני שמתחילים

> **שימו לב: פרוטוקול לא רשמי**
>
> WAHA משתמש בפרוטוקול הלא רשמי של הוואטסאפ (WhatsApp Web מתחת לקלעים), לא ב-API הרשמי של מטא.
>
> משמעות: השתמשו באחריות ובנפח הודעות נמוך. שליחה מסיבית או ספאם עלולים לגרום לחסימה של המספר.
>
> מומלץ לתרגל קודם על מספר משני / מספר בדיקה, ולא על המספר העסקי המרכזי שלכם.
>
> התחילו בקטן, בדקו שהכל תקין, ורק אז הרחיבו.

## טיפים מהניסיון

- שמרו את תיקיית ה-sessions: היא מכילה את החיבור, וכך לא תצטרכו לסרוק QR בכל הפעלה.
- אל תחשפו את מפתח ה-API (X-Api-Key) ואל תעלו את קובץ ה-.env ל-Git.
- התחילו עם המנוע WEBJS: הוא היציב ביותר. עברו ל-NOWEB/GOWS רק אם צריך ביצועים.
- הוסיפו השהיה קטנה (delay) לפני שליחת התשובה, זה נראה טבעי יותר ומפחית סיכון לחסימה.
- בדקו את ה-Swagger המובנה של WAHA (בכתובת /) כדי לראות את כל ה-endpoints הזמינים.
- הריצו את WAHA על שרת / VPS זול שדולק תמיד, כדי שהבוט יענה גם כשהמחשב שלכם כבוי.
- לוגים הם החברים שלכם: הדפיסו כל הודעה נכנסת ויוצאת בזמן הפיתוח כדי לאתר תקלות.
