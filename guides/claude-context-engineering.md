## מה קרה כאן?

אנתרופיק מחקו יותר מ-80% מה-System Prompt של Claude Code עבור המודלים החדשים (Opus 5 ו-Fable 5), **בלי שום ירידה במבחני הקוד שלהם.**

טריק (Thariq), מהנדס בכיר בצוות של Claude Code, פרסם מאמר רשמי בבלוג של Claude עם החוקים החדשים לכתיבת פרומפטים, Skills וקבצי CLAUDE.md. המדריך הזה מסכם אותם בעברית, כולל לולאת השיפור העצמי של בוריס צ'רני.

הרעיון המרכזי: **המודלים החדשים חכמים מספיק. תפסיקו לחנוק אותם בחוקים ובדוגמאות, תנו להם מקום להחליט.**

## החוקים החדשים

### 1. שיקול דעת במקום חוקים נוקשים

פעם כתבו הוראות נוקשות כמו "אף פעם אל תכתוב הערות ארוכות". הבעיה: לפעמים הערה כן נחוצה, והמודל היה מציית לחוק במקום להפעיל שיקול דעת.

היום כותבים הנחיה שנותנת שיקול דעת. הנוסח מהמאמר הרשמי:

```
Write code that reads like the surrounding code:
match its comment density, naming, and idiom.
```

כלומר: "כתוב קוד שנראה כמו הקוד שמסביב". המודל מחליט לבד לפי ההקשר.

### 2. דוגמאות דווקא מזיקות: עצבו ממשק, לא דוגמאות

זה הכי הפוך מהאינטואיציה: כשאתם נותנים לקלוד דוגמה, אתם מכווצים אותו למרחב פתרונות צר. הוא מעתיק את הדוגמה במקום לדמיין פתרון טוב יותר.

במקום דוגמאות: השקיעו בעיצוב הכלים (tools) והממשקים. תנו למודל תיאור ברור של מה הכלי עושה, והוא ימצא את הדרך.

### 3. אל תחזור על עצמך (וגילוי הדרגתי)

הרבה פעמים נוצרות סתירות בין ההוראות: "תעד לפי הצורך" מול "אל תוסיף הערות". סתירות כאלה מבזבזות לקלוד חשיבה לפני שהוא בכלל נוגע בקוד.

במקום להעמיס הכול מראש: השתמשו בגילוי הדרגתי (progressive disclosure): הכניסו הוראות לתיאורי הכלים, והחזיקו עץ של קבצים שנטענים רק כשצריך אותם, בזמן הנכון.

## מה כן שמים ב-CLAUDE.md

הכלל: שמרו על הקובץ רזה. תארו בקצרה למה הריפו משמש, והשקיעו את רוב המילים בדברים שקלוד לא יכול לנחש לבד.

| כן ✓ | לא ✗ |
|---|---|
| Gotchas ומלכודות ספציפיות בקוד | חוקים נוקשים וגורפים |
| מוסכמות לא-ברורות של הפרויקט | דוגמאות קוד ארוכות |
| איפה דברים נמצאים (מבנה) | "המובן מאליו" שקלוד רואה לבד |

## לולאת השיפור העצמי של בוריס צ'רני

בוריס צ'רני, היוצר של Claude Code, עושה משהו חכם בקובץ ה-CLAUDE.md שלו: הוא בונה **לולאת שיפור עצמי.**

הרעיון: שורה שאומרת לקלוד שאחרי כל תיקון שהוא מקבל ממך, הוא בעצמו כותב את הלקח לקובץ נפרד, עם כלל שימנע את הטעות. בתחילת כל שיחה הוא קורא את הלקחים, ומשפר את עצמו עד שהטעויות נעלמות.

**הוסיפו את הקטע הזה ל-CLAUDE.md שלכם:**

```markdown
## Self-improvement loop
After every correction I give you, append the lesson to
.claude/lessons.md as a one-line rule that prevents the mistake.

At the start of every session, read .claude/lessons.md first
and follow every rule until the mistakes stop appearing.
```

איך זה עובד בפועל:

- אתם מתקנים את קלוד פעם אחת
- קלוד כותב את הלקח כחוק חד-שורתי לקובץ הלקחים
- בשיחה הבאה הוא קורא את הלקחים ומתחיל מהם
- אותה טעות לא חוזרת: הקובץ משתפר מעצמו עם הזמן

## בונוס: הפקודה /doctor

לא בא לכם לסדר את הקובץ ידנית? הריצו בטרמינל של Claude Code את הפקודה:

```
/doctor
```

היא בודקת ומייעלת לכם את קובץ ה-CLAUDE.md באופן אוטומטי, מנקה כפילויות, סתירות והוראות מיותרות.

## טיפים מהירים

- רזה מנצח: כל שורה בקובץ מתחרה על תשומת הלב של המודל
- כתבו "למה", לא "מה": המודל כבר יודע איך
- אם אתם כותבים דוגמה: שאלו קודם אם ממשק טוב יותר היה מייתר אותה
- חפשו סתירות: הוראה אחת שסותרת אחרת מזיקה יותר משתיהן ביחד
- העבירו הוראות שימוש בכלי לתוך תיאור הכלי עצמו
- הריצו /doctor אחת לכמה זמן כדי לגזום את הקובץ
